# Chess Review Lab — web UI

A Next.js app for reviewing Chess.com games and solving puzzles generated by the
`chesspipe` pipeline. The game archive starts targeted Stockfish analysis on
demand, then shows an evaluation graph, move classifications, engine lines, and
transparent rule-based coach comments.

## Setup

    cp .env.example .env.local     # then fill in DATABASE_URL etc.
    npm install
    npm run dev                    # http://localhost:3000

`.env.local` (separate from the pipeline's root `.env`, and gitignored):

| var | meaning |
|---|---|
| `DATABASE_URL` | Postgres connection string (same DB as the pipeline). |
| `DB_SCHEMA` | App schema, default `user_chess_analysis`. Applied via search_path. |
| `WEBUI_USER_ID` | Which public.users.user_id's puzzles to serve (matches TARGET_USER_ID). |
| `WEBUI_TIMEZONE` | Timezone used for played/analysis dates, default `Asia/Seoul`. |
| `CHESSPIPE_ROOT` | Optional repository root override for the on-demand analysis worker. |
| `CHESSPIPE_PYTHON` | Optional Python executable override; defaults to `.venv/bin/python`. |
| `LOCAL_OPERATIONS_ENABLED` | Set to `true` to enable Sync/Analyze controls in a local production build. Development enables them automatically. |
| `LICHESS_API_KEY` | Server-side Lichess OAuth token used to identify master-database book moves and opening names. Never expose it as a `NEXT_PUBLIC_` variable. |

## How it works

- `/games` lists imported games and whether their review is ready.
- The Games page can sync Chess.com and analyze the next pending game using the
  Python environment and Stockfish installed on the same computer.
- Sync checks the recent Chess.com archive but imports only URLs not already in
  the database. The archive list uses server-side filters and 40-game pages;
  its header counts the complete archive rather than the current page.
- Selecting a game without an analysis queues that exact `player_games` row and
  launches `chesspipe analyze --player-game-id …`; the page polls until ready.
- `/games/[id]` renders the evaluation graph, review score, move notation,
  critical moments, candidate lines, and comments from deterministic rules.
- The review board is playable. Following the recorded move advances the main
  line; any other legal move creates an autosaved sideline. Saved sidelines can
  be reopened and navigated with the same arrow controls. Right-click a saved
  variation in the notation to delete it.
- `/puzzles` reads the user's puzzles from the DB via
  `server/repositories/puzzles.ts` and passes them to the client WITHOUT the solution.
- `features/puzzles/PuzzleTrainer.tsx` + `components/chess/Board.tsx` render the position and take
  click-to-move input (click a piece, then its target square).
- `app/api/attempt/route.ts` verifies the move server-side against the stored
  `solution_uci`, records the result in `puzzle_progress`, and only then returns
  the solution / forced line.

Move verification checks the puzzle's key (first) move, matching the Telegram
bot's behavior. Promotions default to a queen.

## Notes

- `server/database/postgres.ts` sets search_path at connection time so unqualified table names
  resolve to the app schema, exactly like the pipeline.
- Review scores and comments are Stockfish-based estimates. They do not copy or
  claim to reproduce Chess.com's proprietary accuracy or coaching formula.
- Existing databases must apply `sql/003_review_sidelines.sql` once. Fresh
  databases receive the same table from `sql/001_schema.sql`.
